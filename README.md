# depgraph

Инструмент визуализации графа зависимостей для менеджера пакетов NuGet (.NET).
Практическая работа «Конфигурационное управление», вариант 12.

## 1. Общее описание

Проект выполняется по этапам. Сейчас готов **этап 3**: программа читает настройки из
INI-файла, строит **полный граф зависимостей** пакета (прямые и транзитивные зависимости)
обходом в ширину (BFS) без рекурсии и выводит его на экран. Умеет:

- работать с настоящим репозиторием NuGet (nuget.org) по HTTP;
- работать в тестовом режиме с графом из простого текстового файла;
- пропускать пакеты, в имени которых есть заданная подстрока;
- корректно обрабатывать циклические зависимости.

Порядок загрузки и визуализация будут добавлены на следующих этапах.
Готовые менеджеры пакетов (`dotnet`, `nuget`) и сторонние библиотеки не используются.
Всё делается средствами стандартной библиотеки Java 21: `java.net.http` для запросов,
`javax.xml` для разбора описания пакета. Для тестов нужен JUnit 5.

## 2. Функции и настройки

Конфигурация хранится в INI-файле, секция `[depgraph]`:

| Ключ | Обязателен | Описание |
|---|---|---|
| `package_name` | да | Имя анализируемого пакета. Идентификатор NuGet (буквы, цифры, `.`, `_`, `-`); в тестовом режиме только большие латинские буквы `A-Z` |
| `repository` | да | URL индекса репозитория (`http://` или `https://`) или, при `test_mode = true`, путь к файлу тестового репозитория |
| `test_mode` | да | Режим работы с тестовым репозиторием: `true`/`false` |
| `package_version` | да | Версия пакета: `13.0.3`, `1.2.3.4`, `1.0.0-beta.1` (в тестовом режиме не используется) |
| `filter_substring` | нет | Пакеты, в имени которых есть эта подстрока, не учитываются при анализе (с учётом регистра) |

Синтаксис INI: секции `[имя]`, пары `ключ = значение`, комментарии отдельной
строкой (`;` или `#`). Ключи не зависят от регистра, повторы запрещены.

Аргумент командной строки: путь к INI-файлу (по умолчанию `config.ini` в текущей папке).

### Как строится граф

1. Корневой пакет ставится в очередь.
2. Пока очередь не пуста: берём пакет из начала очереди, узнаём его прямые зависимости,
   добавляем в граф стрелки «пакет зависит от X» и ставим в **конец** очереди те
   зависимости, которых ещё не видели. Так пакеты обходятся по уровням (BFS).
3. Пакеты с подстрокой из `filter_substring` в граф не попадают, их зависимости не
   обходятся. Пустая подстрока ничего не исключает.
4. **Циклы.** Каждый пакет ставится в очередь только один раз (множество уже виденных
   пакетов), поэтому обход всегда заканчивается. Стрелка на уже виденный пакет в граф
   добавляется, и цикл виден в результате. Связи, лежащие на циклах, печатаются отдельной
   строкой.

### Откуда берутся зависимости

**Настоящий репозиторий (`test_mode = false`).**

1. Скачивается индекс (`repository`), например `https://api.nuget.org/v3/index.json`.
   В нём находится сервис `PackageBaseAddress/3.0.0`: адрес хранилища пакетов.
2. Для пакета скачивается описание `{адрес}/{имя}/{версия}/{имя}.nuspec` (XML), из него
   берутся элементы `dependency`.
3. Версия зависимости задана диапазоном (`[13.0.1, )`, `4.3.0`). Как и NuGet, программа
   выбирает самую низкую подходящую версию, то есть нижнюю границу диапазона. Если нижней
   границы нет, берётся самая первая версия пакета из списка версий.

В `.nuspec` зависимости разложены по группам для разных версий платформы .NET. Программа
объединяет все группы.

**Тестовый репозиторий (`test_mode = true`).** `repository` это путь к текстовому файлу.
Одна строка описывает один пакет: `A: B C` значит «A зависит от B и C».
Имена состоят из больших латинских букв. Пустые строки и строки с `#` в начале
пропускаются. Пакет, который нигде не стоит слева от двоеточия, не имеет зависимостей.
Корневой пакет обязан быть описан в файле.

```
# Ромб: от пакета D зависят и B, и C
A: B C
B: D
C: D
D:
```

### Обработка ошибок

Сообщение выводится в stderr, код завершения 1.

- Настройки: файл не найден или это каталог, не читается или не UTF-8, нарушен синтаксис
  INI (с номером строки), неизвестный или пропущенный ключ, пустое значение, неверные
  `test_mode`, имя пакета, URL, путь к тестовому репозиторию, версия; корневой пакет
  содержит подстроку фильтра.
- Получение данных: нет связи с сервером или превышено время ожидания (15 секунд),
  индекс, пакет или версия не найдены (HTTP 404), другой код ответа сервера, в индексе нет
  нужного сервиса, описание пакета не разобрать.
- Тестовый репозиторий: файл не читается, неверная строка (с номером), имя не из больших
  латинских букв, пакет описан дважды, корневой пакет не найден.

## 3. Сборка и тесты

Запуск (сборка и старт): `run.bat` (Windows).

Ручная сборка:

    javac -encoding UTF-8 -d out src/*.java

Тесты (JUnit 5, `junit-platform-console-standalone.jar` положить рядом).
Интернет для тестов не нужен: вместо nuget.org поднимается локальный сервер.

    javac -encoding UTF-8 -d out -cp junit-platform-console-standalone.jar src/*.java tests/*.java
    java -jar junit-platform-console-standalone.jar -cp out --scan-classpath

В IntelliJ IDEA: папка `src` помечена как Sources, `tests` как Test Sources.

## 4. Примеры использования

### Тестовый режим (`scripts\demo_test_repo.bat` запускает все примеры)

Ромб, без циклов (`examples\test_diamond.ini`):

    > run.bat examples\test_diamond.ini
    Граф зависимостей пакета A (пакетов: 4, связей: 4)
      A -> B, C
      B -> D
      C -> D
      D -> (нет зависимостей)
    Циклических зависимостей нет.

Цикл A -> B -> C -> A (`examples\test_cycle.ini`):

    > run.bat examples\test_cycle.ini
    Граф зависимостей пакета A (пакетов: 3, связей: 3)
      A -> B
      B -> C
      C -> A
    Циклические зависимости (связи, которые лежат на цикле): A -> B, B -> C, C -> A

Фильтр `B` (`examples\test_filter.ini`):

    > run.bat examples\test_filter.ini
    Граф зависимостей пакета A (пакетов: 3, связей: 2)
    Фильтр: пакеты, в имени которых есть 'B', пропущены
      A -> C
      C -> D
      D -> (нет зависимостей)
    Циклических зависимостей нет.

Другие примеры: `test_complex.ini` (несколько веток и цикл), `test_self.ini` (пакет
зависит сам от себя), `test_from_c.ini` (граф от другого корня).

### Настоящий репозиторий

    > run.bat examples\logging.ini
    Граф зависимостей пакета Microsoft.Extensions.Logging 8.0.0 (пакетов: 88, связей: 478)
      Microsoft.Extensions.Logging -> Microsoft.Bcl.AsyncInterfaces, Microsoft.Extensions.DependencyInjection, ...
      ...

Граф получается большим, потому что объединяются зависимости для всех версий платформы
.NET, а построение занимает около 15 секунд (сотни запросов к серверу). Циклы в таком
графе возникают из-за этого объединения.

### Ошибки (`scripts\demo_errors.bat` запускает все примеры из `examples\errors`)

    > run.bat examples\errors\test_root_missing.ini
    Ошибка получения данных: пакет Z не найден в тестовом репозитории

    > run.bat examples\errors\test_bad_format.ini
    Ошибка получения данных: тестовый репозиторий, строка 3: ожидается запись вида 'A: B C'

    > run.bat examples\errors\package_not_found.ini
    Ошибка получения данных: пакет No.Such.Package.Xyz123 версии 1.0.0 не найден в репозитории

    > run.bat examples\errors\bad_url.ini
    Ошибка конфигурации: repository: нужен адрес вида https://..., а не 'ftp://example.com'
