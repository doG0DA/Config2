# depgraph

Инструмент визуализации графа зависимостей для менеджера пакетов NuGet (.NET).
Практическая работа «Конфигурационное управление», вариант 12.

## 1. Общее описание

Проект выполняется по этапам. Сейчас готов **этап 2**: программа читает настройки
из INI-файла, обращается к репозиторию NuGet по HTTP и выводит **прямые зависимости**
заданного пакета заданной версии. Построение полного графа, порядок загрузки и
визуализация будут добавлены на следующих этапах.

Готовые менеджеры пакетов (`dotnet`, `nuget`) и сторонние библиотеки не используются.
Всё делается средствами стандартной библиотеки Java 21: `java.net.http` для запросов,
`javax.xml` для разбора описания пакета. Для тестов нужен JUnit 5.

## 2. Функции и настройки

Конфигурация хранится в INI-файле, секция `[depgraph]`:

| Ключ | Обязателен | Описание |
|---|---|---|
| `package_name` | да | Имя анализируемого пакета. Идентификатор NuGet (буквы, цифры, `.`, `_`, `-`); в тестовом режиме только большие латинские буквы `A-Z` |
| `repository` | да | URL индекса репозитория (`http://` или `https://`) или, при `test_mode = true`, путь к файлу тестового репозитория |
| `test_mode` | да | Режим работы с тестовым репозиторием: `true`/`false`. Тестовый режим будет реализован на этапе 3 |
| `package_version` | да | Версия пакета: `13.0.3`, `1.2.3.4`, `1.0.0-beta.1` |
| `filter_substring` | нет | Пакеты, в имени которых есть эта подстрока, будут пропущены при анализе (используется с этапа 3) |

Синтаксис INI: секции `[имя]`, пары `ключ = значение`, комментарии отдельной
строкой (`;` или `#`). Ключи не зависят от регистра, повторы запрещены.

### Как программа получает зависимости (этап 2)

1. Скачивает индекс репозитория (`repository`), например `https://api.nuget.org/v3/index.json`.
2. Находит в индексе сервис `PackageBaseAddress/3.0.0`: адрес, где хранятся файлы пакетов.
3. Скачивает файл описания пакета `{адрес}/{имя}/{версия}/{имя}.nuspec` (имя и версия строчными
   буквами, версия приводится к стандартному виду: `1.0` превращается в `1.0.0`).
4. Разбирает XML и достаёт все элементы `dependency`.

В `.nuspec` зависимости разложены по группам для разных версий платформы .NET
(`net6.0`, `.NETStandard2.0` и т. д.). Программа объединяет все группы, пакет,
повторяющийся в разных группах, выводится один раз.

### Обработка ошибок

Сообщение выводится в stderr, код завершения 1.

- Настройки: файл не найден или это каталог, не читается или не UTF-8, нарушен синтаксис
  INI (с номером строки), неизвестный или пропущенный ключ, пустое значение, неверные
  `test_mode`, имя пакета, URL, путь к тестовому репозиторию, версия.
- Получение данных: нет связи с сервером или превышено время ожидания (15 секунд),
  индекс или пакет или версия не найдены (HTTP 404), другой код ответа сервера,
  в индексе нет нужного сервиса, описание пакета не разобрать.

Аргумент командной строки: путь к INI-файлу (по умолчанию `config.ini` в текущей папке).

## 3. Сборка и тесты

Запуск (сборка и старт): `run.bat` (Windows).

Ручная сборка:

    javac -encoding UTF-8 -d out src/*.java

Тесты (JUnit 5, `junit-platform-console-standalone.jar` положить рядом).
Интернет для тестов не нужен: вместо nuget.org поднимается локальный сервер.

    javac -encoding UTF-8 -d out -cp junit-platform-console-standalone.jar src/*.java tests/*.java
    java -jar junit-platform-console-standalone.jar -cp out --scan-classpath

В IntelliJ IDEA: папка `src` помечена как Sources, `tests` как Test Sources.
